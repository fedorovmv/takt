# Waves 0-1-2 Release, Compatibility, and Evidence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the release/backlog truth, supported host compatibility gates, and authored evaluation path into alignment without removing or disabling the public micro DSL/evaluation surface.

**Architecture:** Keep Takt's single stable runtime and existing `appapi`/compatibility registry. Wave 0 changes only version and planning truth. Wave 1 adds deterministic CI coverage and explicit live-compatibility evidence plumbing; it must never promote a host from `guarded` to `strict` from a version probe alone. Wave 2 keeps the authored ordinary-Run evaluation path canonical, preserves the legacy reader window, and exposes a clear migration/adapter smoke contract.

**Tech Stack:** Go, Make, GitHub Actions, Markdown contracts, existing compatibility matrix, `takt-evaluation/v1alpha1`, route/micro DSL examples and deterministic Go E2E tests.

**Spec:** `docs/archive/analysis/2026-08-21-gap-backlog-audit.md`

## Global Constraints

- Keep the local single-user trusted-runtime scope; do not add server, database, Web UI, remote workers, or multi-user auth.
- Keep the route/micro DSL, its examples, validators, benchmarks, and evaluation fixtures in the open-source tree and enabled in deterministic tests.
- `strict_allowed` requires actual host conformance; a binary version probe only produces a warning.
- Product behavior after `v0.1.63-alpha` reserves `v0.1.64-alpha`; root `VERSION` and `internal/version.Value` must match.
- External credentials/model runs are evidence inputs, not required for deterministic CI.
- Every behavior change gets a Go unit/contract/E2E regression test before implementation.
