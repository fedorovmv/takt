# Каталог процессов разработки и умный роутер v0.1.24

## Цель среза

Срез переносит в профиль `code` полный набор из 19 типовых процессов разработки, представленных в Archon, и добавляет функции runtime, без которых эти процессы пришлось бы упрощать. Takt сохраняет собственный формат и архитектуру: каждый процесс компилируется в один DAG, использует один Run, один журнал событий и одну модель возобновления.

## Каталог профиля `code` 0.4.0

## Умный роутер

Запуск без суффикса использует `code-router`:

```bash
takt run code --input "Исправь issue #123 и создай PR"
```

Первый узел `route` получает запрос и возвращает JSON:

```json
{"workflow":"fix-github-issue","reason":"Запрос содержит существующее issue и требует реализации"}
```

`output_format` проверяет структуру, обязательные поля и допустимое имя workflow. После этого условие по `nodes.route.output.workflow` открывает ровно одну ветку. Роутер остаётся частью того же Run, поэтому его решение, модель, расход, попытки и результат видны в состоянии и журнале событий.

Прямой выбор сохраняется:

```bash
takt run code:comprehensive-pr-review --input "Проверь текущий PR"
takt workflow list code
takt workflow describe code:piv-loop
```

## Новые функции runtime

### Именованные workflow профиля

`profile.yaml` поддерживает карту `workflows`. Селектор `profile:name` выбирает конкретный файл. CLI предоставляет `workflow list` и `workflow describe`.

### Проверяемый структурированный вывод

Узлы `command` и `prompt` поддерживают `output_format` — компактное подмножество JSON Schema:

- `object`, `array`, `string`, `boolean`, `number`, `integer`;
- `properties`, `required`, `enum`, `items`;
- `additionalProperties`.

Успешный ответ должен содержать ровно одно JSON-значение. Результат проверяется и приводится к компактной записи. Нарушение контракта становится ошибкой `protocol`; native attempts policy может повторить узел и передать точную ошибку через `${feedback}`. Raw stdout провайдера при нормализации не изменяется.

### Поля JSON в шаблонах и условиях

Доступны вложенные пути:

```yaml
when: nodes.route.output.workflow == "assist"
prompt: "Сложность: ${nodes.classify.output.details.level}"
```

Поддерживаются поля объектов и числовые индексы массивов.

### Параллельный scheduler

Независимые готовые узлы `command`, `prompt` и `bash` без переносимых hooks и автоматических повторов запускаются одновременно. Переходы состояния и запись событий выполняются последовательно до и после параллельной волны. Runtime сохраняет один Run и ожидает завершения всех узлов волны по модели `all settled`.

Параллельность используется для сбора контекста, независимых проверок PR и других операций чтения. Workflow должен явно задавать зависимости для узлов, которые читают результаты друг друга или изменяют общие файлы в определённом порядке.

### Параллельный `foreach`

```yaml
foreach:
  parallel: true
  items: [code, tests, docs]
  subworkflow:
    path: review.yaml
```

Итерации получают общую зависимость от входного gate и выполняются тем же scheduler. Итоговый JSON-массив сохраняет порядок исходных элементов, а не порядок завершения.

### Возобновляемое участие человека внутри цикла

`approval` разрешён внутри `loop_group`. Активная итерация записывается в `NodeState.loop_iteration`. После `takt answer` runtime продолжает существующие дочерние состояния, а не создаёт их повторно. После завершения итерации ответ удаляется, поэтому следующая итерация снова запрашивает решение пользователя. Последняя итерация сохраняется в `loop_previous`.

### Дополнительная семантика DAG

Добавлено правило `one_success`: узел запускается, когда все зависимости завершены и хотя бы одна имеет статус `completed`, даже если другие были пропущены или завершились ошибкой. Оно используется для объединения условных ветвей и результатов выборочных ревью.

Команды для workflow, расположенного в подкаталоге профиля, ищутся в `commands/` рядом с ним и далее в родительских каталогах до workspace. Это позволяет запускать именованный workflow напрямую без копирования общего набора команд.

## Функциональные пробелы относительно платформы Archon

Каталог процессов перенесён полностью по назначению и этапам. Оставшиеся различия относятся к инфраструктуре исполнения, а не к отсутствующим workflow:

| Возможность Archon | Состояние Takt |
|---|---|
| Автоматическое создание отдельного git worktree для Run | Реализовано: direct workflow создаёт worktree при старте, router — на gate выбранного дочернего workflow |
| Governed child run с отдельным Run ID, стоимостью и артефактами | `subworkflow` компилируется в родительский DAG и общий Run |
| Ограничение `allowed_tools`, `denied_tools`, per-node skills и MCP-конфигурации | Набор инструментов задаёт внешний coding assistant; runtime пока не меняет его на уровне узла |
| `script`-узлы Bun/uv | Используются `bash` и инструменты внешнего агента |
| `output_type` и индекс типизированных артефактов | Процессы записывают именованные файлы в `$ARTIFACTS_DIR` |
| Узел `cancel` и отмена через CLI | Отмена через отдельную команду Takt ещё не реализована |
| Требования подключённой GitHub-учётной записи до запуска | Проверка `gh` выполняется внутри процесса |
| Web UI, сервер, БД и адаптеры | Оставлены как proposal: текущий scope — локальный однопользовательский trusted runtime |

Эти пункты нельзя имитировать полями YAML. Для них нужны отдельные контракты безопасности, изоляции и интеграции. Процессы, которым нужны GitHub, Remotion или браузерные инструменты, используют возможности настроенного OpenCode/Pi и завершаются понятной ошибкой, если внешний инструмент отсутствует.

## Проверки

Контракт профиля проверяет:

- наличие всех 19 файлов;
- загрузку и `takt validate` каждого селектора;
- загрузку роутера;
- вывод `workflow list` и `workflow describe`;
- запуск одной ветки роутера с mock assistant;
- параллельное выполнение независимых узлов;
- параллельный `foreach` с сохранением порядка результатов и его фактическое использование в полном review block;
- два последовательных approval внутри одного `loop_group`;
- проверку и нормализацию структурированного ответа;
- обращения к полям JSON в `when` и шаблонах.
