# Описание проекта

## Проблема

Команды, экспериментирующие с агентной разработкой, часто зашивают стратегию выполнения в код:

- один или несколько агентов;
- общий или новый контекст на каждой попытке;
- фиксированные роли или свободные инструкции;
- детерминированные или LLM-проверки;
- разные модели на этапах;
- точки участия человека;
- повтор отдельного шага или целого подграфа.

Каждая новая гипотеза приводит к перестройке приложения. Результаты экспериментов сложно воспроизводить и сравнивать.

## Цель

Создать универсальный Go-runtime, в котором стратегия задаётся файлами конфигурации, а код ядра отвечает только за выполнение:

- загрузку и проверку workflow;
- разрешение моделей, исполнителей и Markdown-команд;
- выполнение DAG;
- циклы и условия завершения;
- внешние проверки и обратную связь;
- ожидание ответа человека;
- хранение состояния, событий и артефактов.

## Что проект не делает

Проект не реализует ещё одного кодового агента. Он не содержит собственного многошагового tool-calling цикла, файловых инструментов для модели, LSP, памяти проекта или системы субагентов.

Эти функции предоставляет выбранный исполнитель: Pi, OpenCode, Codex, Claude Code либо другой агент.

## Основной сценарий

```text
workflow
  → Markdown-команда
  → кодовый агент с выбранной моделью
  → внешняя проверка
  → обратная связь и новая попытка
  → approval
  → итоговые артефакты
```

## Критерий универсальности

Ядро считается универсальным, если без изменения Go-кода можно описать как минимум три несвязанных процесса:

1. генерацию Route DSL;
2. исправление ошибки в Go-проекте;
3. подготовку технического документа с согласованием.
