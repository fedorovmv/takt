# Описание проекта

## Кратко

Takt — локальный runtime, который исполняет проверяемые процессы поверх
готовых кодовых агентов, моделей и детерминированных инструментов. Он отделяет
логику координации от конкретного coding-agent host и сохраняет каждый запуск
как наблюдаемый и продолжаемый Run.

## Проблема

Команды, использующие агентов в разработке, часто зашивают стратегию
исполнения непосредственно в приложение или prompt:

- какой агент и модель выполняют каждый этап;
- какие шаги независимы и могут идти параллельно;
- когда запускать детерминированную проверку;
- что повторять после ошибки и в каком контексте;
- где требуется решение человека;
- какие результаты считать доказательством завершения.

При таком подходе изменение стратегии требует переписывать управляющий код,
а результаты сложно воспроизводить, сравнивать и продолжать после сбоя.

## Цель

Цель Takt — сделать процесс явным и проверяемым. Workflow описывает
координацию, Config связывает логические роли с моделями и исполнителями, а
runtime отвечает за:

- загрузку и проверку определений до запуска;
- выполнение DAG, циклов и управляемых дочерних Run;
- retries, timeout, cancellation и approval;
- детерминированные проверки результата;
- хранение состояния, событий, usage и артефактов;
- безопасное продолжение и восстановление локального запуска.

## Для кого

Takt рассчитан на разработчиков и небольшие команды, которым нужен локальный,
воспроизводимый control plane для агентных процессов без отдельного сервера и
без привязки workflow к одному coding-agent host.

## Основные сценарии

1. Запустить кодового агента, проверить результат скриптом и вернуть feedback
   в повторную попытку.
2. Выполнить несколько независимых проверок параллельно и агрегировать их
   результаты.
3. Остановить Run на approval, сохранить его состояние и продолжить позже.
4. Изолировать изменение в Git worktree и сохранить итоговые артефакты.
5. Сравнить несколько стратегий или моделей на одинаковом наборе задач.
6. Управлять длительными локальными Run через CLI, MCP или daemon.

Типовой поток выглядит так:

```text
workflow
  → coding agent или deterministic action
  → проверяемый результат
  → retry / next branch / approval
  → durable state и артефакты
```

## Принципы

- **YAML координирует. Код вычисляет. Агент принимает решения.**
- Текст агента не является доказательством успеха: итог подтверждает
  детерминированная проверка.
- Все способы запуска используют один scheduler и одну семантику Run.
- Возможности исполнителя проверяются до его запуска и не игнорируются молча.
- Состояние, события и артефакты сохраняются так, чтобы Run можно было
  наблюдать, продолжить или расследовать.
- Новая абстракция появляется только при подтверждённой необходимости.

## Что проект не делает

Takt не реализует собственного многошагового tool loop, файловых инструментов
для модели, LSP, память проекта или внутреннюю систему субагентов. Эти функции
предоставляет Pi, OpenCode или другой совместимый исполнитель.

В текущий scope также не входят:

- сетевой или многопользовательский сервер;
- Web UI и база данных;
- выполнение workflow от недоверенных пользователей;
- универсальный plugin framework;
- встроенное хранилище секретов;
- distributed workers и remote execution.

## Модель доверия и зрелость

Текущая линия `v0.1.x-alpha` предназначена для одного пользователя и
доверенного локального workspace. Workflow, Config, scripts, adapters и
подключаемые packages являются исполняемым доверенным содержимым. Подробности
зафиксированы в [`SECURITY.md`](../SECURITY.md).

Stable core уже покрывает основной жизненный цикл Run. Extensions,
experimental-функции и tooling имеют отдельные уровни стабильности. Фактическое
состояние перечислено в
[`05-implementation-status.md`](05-implementation-status.md), а дальнейшие
приоритеты — в [`06-roadmap.md`](06-roadmap.md).

## Критерии успеха проекта

Takt выполняет свою задачу, если:

- один и тот же Workflow воспроизводимо запускается с разными совместимыми
  исполнителями;
- изменение стратегии не требует изменения scheduler-кода;
- terminal outcome подтверждается проверяемыми evidence, а не заявлением
  агента;
- остановленный Run можно объяснить и безопасно продолжить;
- локальная эксплуатация не требует отдельного сервера или БД;
- новые возможности не размывают границу между orchestration runtime и coding
  agent.
